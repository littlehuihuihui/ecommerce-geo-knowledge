# 养老金全链路业务流程 · 概念与思路（HK 强积金为主）

> 目的：把岗位要求里的 **受托人 / 雇主 / 参保人 / 平台** 说清楚——谁在什么阶段做什么、常见诉求怎么拆。  
> 配套：`role_stage_matrix.csv` · `ticket_interpretation.csv` · `business_chain_dashboard.html`

---

## 1. 一张图：端到端主链路

```
[监管 MPFA] 监督计划与受托人
      │
[平台 eMPF] 标准化登记·供款·转移·查询·提取通道
      │
      ├─ 雇主 ──登记计划──► 登记雇员 ──► 每月供款汇付 ──► 对账/催收/违规处理
      │
      ├─ 参保人(雇员/自雇) ──入职登记──► 选基金/DIS ──► 自愿供款/帐户整合
      │                              ──► 转职转移 / 雇员自选 ──► 退休·提早·离港提取
      │
      └─ 受托人 ──收供款入账──► 分配至成分基金 ──► 权益记录 ──► 服务时效·投诉·披露(TER)
```

和现有「对象一～四」的关系：

| 对象一～四 | 本链路模块 |
|------------|------------|
| 问：池子多大、个人够不够 | 问：**谁推动供款进来、谁把钱记对、谁办提取** |
| 输出：亿港元 / 替代率 | 输出：**流程阶段 + 业务诉求解读** |
| eMPF = 费率扣减 | eMPF = **平台角色**（工单、时效、集中度） |

## 2. 四角色分别「负责什么」

### 2.1 雇主（Employer）

| 阶段 | 关键动作 | 典型时限/规则（教学锚点） |
|------|----------|---------------------------|
| 开业合规 | 开业后登记强积金计划 | 常见口径：**60 天内**登记 |
| 雇员入职 | 为合资格雇员登记账户 | 入职后按规定时限完成 |
| 月度供款 | 按有关入息扣雇员 5% + 缴雇主 5%；受上下限约束 | 供款日 / 足额双重合规 |
| 异动 | 离职、遣散、长服金与**取消对冲**后的处理差异 | 2025-05-01 转制后雇主强制一般不可对冲 |
| 风控 | 应对积金局催缴、检控与罚款 | 百科「违规雇主数」指标 |

**雇主侧业务诉求关键词**：登记逾期、供款失败、薪资系统对不上、自雇误判、对冲争议。

### 2.2 参保人（成员 Member）

| 阶段 | 关键动作 | 诉求焦点 |
|------|----------|----------|
| 入职 | 确认已有账户 / 新开 / 选计划 | 「公司有没有帮我开」 |
| 积累 | 基金选择、DIS、自愿供款、查结余 | 「回报差 / 费用高」 |
| 在职流动 | 转职后多账户、整合、全自由行/雇员自选 | 「账户太散」 |
| 领取 | 65 岁一笔过/分期、提早提取、离港 | 「怎么取、要几天」 |
| 与第一支柱衔接 | 长津/综援/生果金资格（对象外延） | 「有强积金还能领津贴吗」→ 见三层模块 |

**参保人侧关键词**：查余额、转基金、整合账户、提取进度、投诉服务态度。

### 2.3 受托人（Trustee）

| 阶段 | 关键动作 | 运营质量度量（对齐百科） |
|------|----------|--------------------------|
| 收付 | 接收雇主汇付并入账分配 | 雇主支付→入账平均天数 |
| 记录 | 成员权益准确性、单位价格 | 对账差异率 |
| 服务 | 查询、转移、提取申请处理 | 服务时效、投诉率、NPS |
| 产品 | 成分基金、DIS、TER 披露 | 费率与长期净回报 |
| 合规 | 向积金局报备、反洗钱、利益冲突 | 合规事件数 |

**受托人侧关键词**：供款批处理失败、NAV 异常、提取 SLA、跨计划转移堵点、eMPF 切换并行。

### 2.4 平台（eMPF / 集中行政）

| 能力 | 业务含义 | 与模型关系 |
|------|----------|------------|
| 统一入口 | 降低「多受托人多门户」摩擦 | 对象一**不**模拟竞争，但本模块讲清平台价值 |
| 标准化工单 | 登记、供款、转移、提取同一套状态机 | 诉求解读靠工单状态 + SLA |
| 费率 | 行政费约 **0.29%**（公开教学锚点，以官方最新为准） | 对象一净回报已扣 |
| 全自由行 | 账户可携带性增强 → 受托人竞争 | 面试包已标「未建模受托人层」——此处补**业务叙事** |

## 3. 「精准解读业务诉求」四步法

接到一句口语诉求时，按固定顺序拆（面试可背）：

1. **定角色**：说话的人是雇主 / 成员 / 受托人运营 / 平台甲方？  
2. **定阶段**：覆盖登记 → 供款 → 投资服务 → 转移 → 提取 → 投诉合规，卡在哪一环？  
3. **定对象**：账户？款项？时效？资格？系统？政策？  
4. **定证据**：该拉哪张表 / 哪个北极星指标 / 哪段法规口径？

例：「为什么这个月薪水扣了强积金但账户还没到账？」

| 步 | 解读 |
|----|------|
| 角色 | 参保人（也可能是雇主财务代问） |
| 阶段 | 供款汇付 → 受托人/平台入账 |
| 对象 | 时效 + 对账 |
| 证据 | 供款日、汇付批次号、入账 SLA、对账差异；排除「低于下限雇员部分可不供」误解 |

## 4. 生命周期 × 角色责任矩阵（摘要）

详见 `role_stage_matrix.csv`。阶段划分：

1. 计划/雇主登记  
2. 成员登记与开户  
3. 月度供款与入账  
4. 投资选择与服务  
5. 转职/转移/整合  
6. 权益支付（提取）  
7. 投诉、稽查与合规  

每一格写：**主责角色、依赖角色、成功标准、失败时典型诉求**。

## 6. 局限

- 未建受托人市场份额仿真、未建真实工单系统。  
- 内地年金「受托人—账管—托管—投管」四类人资格与香港用语不完全等同，类比时需声明。  
- 时限与罚则请以积金局最新公开资料为准。
