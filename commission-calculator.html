一、这个工具在算什么？

面向港资通信设备销售的每月佣金处理：先按销售员汇总销售额与应发佣金（月结主交付）， 再用规则引擎处理退货冲销、回款归属、SKU/阶梯差异，并以异常闸门与勾稽校验保障发薪 SLA 质量。

二、核心业务概念

计算周期 Period

本次要结算的月份（如 2025-03）。只有「归属月 = 计算周期」的订单，才会计入汇总卡片的销售额与佣金。

归属 Attribution

决定一笔单记入哪个月。默认按回款月（钱到账才发佣）；也可切到按订单月（开单即计提，用于对比口径差异）。

佣金规则表 Rule Table

一套规则 = 一张表，一条细规则 = 一行：计划 / 产品组 / 金额区间 / 比例 / 系数 / 规则类型 / 有效期。低额单低比例、高额单高比例；Router 1.0、Enterprise Line 1.5、SIM Plan 0.8 调节「同样销售额下的佣金含金量」；支持封顶、保底、加速器、SPIFF 一次性奖励。

基础佣金 Base

正常销售单（非退货）按公式算出的应发提成，尚未扣减退货。规则未匹配时记 0，并打异常。

退货冲销 Return Clawback

return_flag = Y 的单据不进正常提成；若开启扣减，则按同等公式算出扣减额，从归属月佣金中冲回，避免「货退了佣金还留着」。

跨期 Cross-period

订单月 ≠ 回款月。常见于账期客户。无论用哪种归属规则，都必须标记，防止同一笔在两个月争议。

异常稽查 Anomaly

不是简单标红，而是按判定条件产出可处理清单：退货冲销、跨期归属、重复计算、规则未匹配，并给出建议动作。

产品线 Product Line

本工具覆盖 CPE 设备（Router / Switch）与线路/连接类产品（SIM Plan / Enterprise Line），模拟港资通信公司「设备 + 线路」打包销售。

三、核心公式

基础佣金 = 销售额 × 阶梯提成比例 × SKU 系数
退货扣减 = 退货金额 × 阶梯提成比例 × SKU 系数　（仅 return_flag = Y 且开启「扣减当月佣金」）
最终佣金（本期） = 基础佣金 − 退货扣减
例：销售额 93,400 · 落入 3% 档 · Switch 系数 1.2 → 基础佣金 = 93,400 × 3% × 1.2 = 3,362.40

四、严格计算顺序（七步，不可调换）

  1. ① 过滤退货单：return_flag = Y 不进入正常提成链路，转入冲销逻辑；N 继续往下走。
  2. ② 判定归属月：按「回款月 / 订单月」规则（退货可选手动追溯原订单月）得到归属月，并判断是否纳入当前计算周期。
  3. ③ 匹配佣金规则：按 判定日 → 计划 → 产品（SKU 前缀优先、产品线次之、All 通配兜底）→ 金额区间 命中一行规则；未命中 →「规则未匹配」，佣金记 0。
  4. ④ 按规则类型计算：默认阶梯比例 = 金额 × 比例 × 系数；规则类型还支持封顶、保底、加速器、SPIFF 一次性奖励。
  5. ⑤ 计算基础佣金：仅非退货且规则齐全时：金额 × 比例 × 系数；中间值可在明细行展开查看。
  6. ⑥ 退货冲销扣减：扣减金额单独字段，不与基础佣金混算；记录扣哪一单、扣多少、扣到哪个月。
  7. ⑦ 输出明细 + 异常表：本期汇总只加「归属月 = 计算周期」的行；全量明细保留他月行（标「非本期」）便于追溯。
口径提醒：汇总卡片 / 勾稽 / 销售员汇总 = 本期口径。 佣金明细默认筛选「仅本期（与汇总一致）」；若需追溯他月，可切换为「全部月份」（非本期行会标灰）。

新增规则

阶梯比例：基础佣金 = 金额 × 比例 × 系数。

退货扣减规则

扣减当月佣金
return_flag = Y 的订单：不进入正常提成计算；若开启本开关，则按「销售额 × 阶梯比例 × SKU 系数」的绝对值从归属月佣金中扣减（冲销）。
追溯原订单月份（可选）
开启后：退货冲销的归属月取原订单月（order_date）；关闭时：跟随当前回款归属规则（默认回款月）。用于财务要求“冲销回到原计提月”的场景。
退货锁定原单政策（推荐）
开启后：冲销按原销售单回款日命中的政策版本计算扣减，避免月中改政策导致「发 3%、退按 3.5% 扣」。关闭则按退货判定日重新匹配政策。
允许负佣金挂账
开启：销售员本期最终佣金可为负（扣减超过应发，挂下月抵扣）。关闭：个人最终佣金截断为 0，差额记入「负佣截断」披露。

回款状态口径

payment_status：paid 全额回款按 amount 计提； partial 按 paid_amount 计提（未回部分不进佣金）； unpaid 待回款——明细可见、不进任何月结。空 payment_date 且未标明时按 unpaid 推断。

设计逻辑

  1. 先月结产出、再质量闸门：销售运营月结的第一交付是「每人销售额与应发佣金」；异常与勾稽用于保证发薪质量，而不是替代主报表。
  2. 为什么按回款归属：开单不等于收入确认。通信设备项目常有账期，按回款月计提佣金可对齐财务现金流，避免“未回款先发佣、退货再追回”的混乱。
  3. 回款状态机：unpaid 挂起不计提；partial 仅按已回款金额计提；paid 全额计提。待回款进明细披露，不阻塞发薪。
  4. 为什么退货要单独扣减：退货不是普通负销售额混算。单独冲销可保留原单计算痕迹；默认锁定原单政策，防止月中改版扯皮；累计退货超额则阻塞发薪。
  5. 负佣金：默认允许负余额挂下月；也可截断为 0 并披露截断额，两种政策可切换。
  6. 为什么异常要单独稽查：重复计算与规则未匹配会阻塞发薪；跨期与退货需披露。单独异常表让运营/财务按类型处理，满足月结 SLA。
  7. 为什么规则要可配置：产品线系数与阶梯比例会随政策变化。规则表可编辑，对应「自动化人工佣金计算、改规则不改代码」。
  8. 政策时间轴：方案按生效起止前后衔接（A→B→C）。新增方案默认明天起生效，上一版「至今」自动止于今天；可改生效起。
  9. 为什么明细要可追溯：从销售员月结下钻到订单链路，便于核对「这一笔是怎么算出来的」。
  10. SKU 系数与阶梯分离：阶梯反映规模激励，系数反映产品权重；两者解耦后改政策只需改对应表。
  11. ETL / Power Apps：本工具演示计算与质量闸门；生产可用 Power Automate + SQL/Dataverse 承接同一套规则与审批流。

English Note

This is a monthly commission processing workbench for telecom equipment sales. It first produces a sales-rep payroll summary (sales and commission by person), then applies configurable tiered rates, SKU coefficients, return deductions, and payment-based attribution. Anomaly gates and reconciliation support SLA quality before payout. A production roadmap maps the flow to Power Platform and ETL/BPM models.
