一、这个工具在算什么？

面向港资通信设备销售场景：销售员卖出 Router / Switch / SIM Plan / Enterprise Line 后，公司按月结算佣金。 核心问题不是「把金额乘个比例」，而是：哪些单能进本期、按什么规则加权、退货怎么冲、哪里算错了要单独揪出来。

二、核心业务概念

计算周期 Period

本次要结算的月份（如 2025-03）。只有「归属月 = 计算周期」的订单，才会计入汇总卡片的销售额与佣金。

归属 Attribution

决定一笔单记入哪个月。默认按回款月（钱到账才发佣）；也可切到按订单月（开单即计提，用于对比口径差异）。

阶梯提成 Tier Rate

按单笔销售额落入的金额区间匹配提成比例。低额单低比例、高额单高比例，用于激励做大单。

SKU / 产品线系数 Coefficient

不同产品线毛利与战略权重不同。例如 Enterprise Line 系数 1.5、SIM Plan 0.8，用来调节「同样销售额下的佣金含金量」。

基础佣金 Base

正常销售单（非退货）按公式算出的应发提成，尚未扣减退货。规则未匹配时记 0，并打异常。

退货冲销 Return Clawback

return_flag = Y 的单据不进正常提成；若开启扣减，则按同等公式算出扣减额，从归属月佣金中冲回，避免「货退了佣金还留着」。

跨期 Cross-period

订单月 ≠ 回款月。常见于账期客户。无论用哪种归属规则，都必须标记，防止同一笔在两个月争议。

异常稽查 Anomaly

不是简单标红，而是按判定条件产出可处理清单：退货冲销、跨期归属、重复计算、规则未匹配，并给出建议动作。

产品线 Product Line

本工具覆盖 CPE 设备（Router / Switch）与线路/连接类产品（SIM Plan / Enterprise Line），模拟港资通信公司「设备 + 线路」打包销售。

三、核心公式

基础佣金 = 销售额 × 阶梯提成比例 × SKU 系数
退货扣减 = 退货金额 × 阶梯提成比例 × SKU 系数　（仅 return_flag = Y 且开启「扣减当月佣金」）
最终佣金（本期） = 基础佣金 − 退货扣减
例：销售额 93,400 · 落入 3% 档 · Switch 系数 1.2 → 基础佣金 = 93,400 × 3% × 1.2 = 3,362.40

四、严格计算顺序（七步，不可调换）

  1. ① 过滤退货单：return_flag = Y 不进入正常提成链路，转入冲销逻辑；N 继续往下走。
  2. ② 判定归属月：按「回款月 / 订单月」规则（退货可选手动追溯原订单月）得到归属月，并判断是否纳入当前计算周期。
  3. ③ 匹配 SKU 系数：优先按 product_line，其次按 SKU 前缀；未命中 →「规则未匹配（SKU缺失）」，系数空、佣金记 0。
  4. ④ 匹配阶梯区间：销售额落入哪一档用哪一档比例；未落入任何档 →「规则未匹配（阶梯缺失）」。
  5. ⑤ 计算基础佣金：仅非退货且规则齐全时：金额 × 比例 × 系数；中间值可在明细行展开查看。
  6. ⑥ 退货冲销扣减：扣减金额单独字段，不与基础佣金混算；记录扣哪一单、扣多少、扣到哪个月。
  7. ⑦ 输出明细 + 异常表：本期汇总只加「归属月 = 计算周期」的行；全量明细保留他月行（标「非本期」）便于追溯。
口径提醒：汇总卡片 / 勾稽 / 销售员汇总 = 本期口径。 佣金明细默认筛选「仅本期（与汇总一致）」；若需追溯他月，可切换为「全部月份」（非本期行会标灰）。

设计逻辑

  1. 为什么按回款归属：开单不等于收入确认。通信设备项目常有账期，按回款月计提佣金可对齐财务现金流，避免“未回款先发佣、退货再追回”的混乱。
  2. 为什么退货要单独扣减：退货不是普通负销售额混算。单独冲销可保留原单计算痕迹，支持审计追溯：扣的是哪一单、扣多少、扣到哪个月。
  3. 为什么异常要单独稽查：跨期、重复、规则未匹配会直接扭曲提成结果。单独异常表让运营/财务可按类型分工处理，而不是在明细海里肉眼找红字。
  4. 为什么规则要可配置：产品线系数与阶梯比例会随季度促销、渠道政策变化。把规则做成可编辑表，避免把业务常量写死在代码里。
  5. 为什么明细要可追溯：结算对账时常被问到“这一笔是怎么算出来的”。展开计算链路（过滤→归属→系数→阶梯→冲销）便于核对与审计。
  6. SKU 系数与阶梯分离：阶梯反映规模激励，系数反映产品毛利/战略权重；两者解耦后，改政策时只需改对应表，不必重写公式。
  7. 跨期必须显式标记：订单月≠回款月时，无论采用哪种归属规则，都应提示“是否纳入本期”，防止报表口径争议。
  8. 为什么要有勾稽校验：结算错一分钱会被追责。本工具用多口径交叉核对：汇总恒等式、本期明细加总≡汇总、销售员汇总≡总表、逐行最终佣金逻辑；若存在重复单还会提示「虚增金额，发薪前须去重」。
  9. 部分退货怎么处理：样例含 HK-2503-039（销售额 90,000）与 HK-2503-039R（退货 45,000，orig_order_id 指向原单）。冲销按退货金额重算扣减，而非简单整单作废；生产还可扩展数量占比冲销。

English Note

This is a commission calculator for telecom equipment sales. It supports configurable tiered rates, SKU-based coefficients, return deductions, and payment-based attribution. It flags four types of anomalies: return reversals, cross-period attribution, duplicates, and unmatched rules. Reconciliation cross-checks period totals against sales-rep rollups and per-row logic, and warns when duplicates inflate payout. A production roadmap maps each feature to the Power Platform and to a BPM/ETL data model (this tool uses a wide table; production typically splits order and payment facts).
